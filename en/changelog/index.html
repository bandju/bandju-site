Updates

BandjuPanel changelog

Public release history by version.

Download

Version 1.8.0

Latest release
  • Added a new Backups section for saving services, settings, and accesses to a local file.
  • A clean VPS can be fully restored, while a configured VPS can safely import accesses without overwriting its current settings.
  • Before restoring, panel shows a detailed plan and checks compatibility, missing services, ports, domain, and DNS.
  • Added VPS-to-VPS migration: IP and domain settings are adapted, while connections that need a new config or rebinding are marked separately.
  • Updated AmneziaWG v3 to version 3.1.
  • Added domain endpoints for AmneziaWG legacy, v2, and v3, with DNS validation and backup support.
  • Updated Hysteria2 to version 2.12.2 and improved the reliability of tests, WARP, and background state refreshes.
  • Migrated Cascade to AmneziaWG 3.1, improved automatic tunnel recovery, and added VPS resource and connection-capacity checks.
  • Fixed access sorting by aggregate traffic and made background list refreshes faster without unnecessary VPS load.
  • Hysteria2 technical logins are now labeled explicitly so they are not mistaken for IP addresses.
  • Improved launcher recovery after temporary connection failures and clarified launcher and panel update states.
  • Added safe VPS storage maintenance to limit log growth and clean up old unused cache data.

Version 1.7.0

  • Added a dark theme and refreshed the app appearance, including integrated window chrome.
  • Separated launcher and panel updates, with each component's status shown independently.
  • Added AmneziaWG 3.0 support for compatible clients.
  • Added advanced XHTTP settings for Xray and Salamander obfuscation settings for Hysteria2.
  • Added subscription connection ordering controls.
  • Made success notifications more prominent and added clear access icons to Hysteria2 links.
  • Expanded VPS diagnostics with external reachability checks and IP and service region detection.
  • Improved license recovery guidance and transfer confirmation reliability.
  • Fixed ingress IP detection behind Cascade and MTProto and Gateway lifecycle handling.
  • Improved panel background checks and update handling.

Version 1.6.2

  • Launcher updates are now available directly in the app on Windows and macOS. After installing 1.6.2, future versions can be installed without replacing the app manually.
  • Settings, saved VPS servers, and the license remain intact during updates.
  • Launcher and panel can now be updated independently, so an unchanged component does not need to be reinstalled.
  • Improved license system protection and stability.
  • Improved panel installation and update reliability during temporary external source outages.

Version 1.6.1

  • The launcher now verifies that the open SSH tunnel belongs to the selected VPS before installing or updating panel.
  • Improved stale SSH tunnel cleanup on Windows; if the local port is occupied by another process, the launcher safely stops the operation and shows clear guidance.
  • The launcher automatically repairs overly broad file permissions on SSH keys it created in Windows without replacing the keys. Imported custom keys remain unchanged.
  • Added clear diagnostics for the known SSH incompatibility with Ubuntu 26.04 and guidance to use Ubuntu 22.04 or 24.04 LTS.
  • Fixed source VPS detection for external connections after a server is renamed or added again.
  • When a match is ambiguous, the launcher no longer selects a source VPS automatically, preventing the operation from running on another server.
  • Doctor no longer shows an incorrect warning about outdated XRay links after connection settings change.

Version 1.6.0

  • Bandju Panel now supports Hysteria2, a fast UDP/QUIC proxy protocol designed for unstable networks with packet loss and high latency. It helps maintain speed where conventional TCP connections lose significant performance and disguises the connection as standard HTTP/3 traffic.
  • Hysteria2 can use a direct route, WARP, or Cascade. Hysteria2 connections from external VPS servers can also be added to shared Bandju subscriptions.
  • Hysteria2 can now be routed through Cascade.
  • Improved the stability of Cascade startup and switching between Direct and WARP.
  • If switching fails, Bandju Panel attempts to restore the previous mode automatically.
  • Improved recovery after a temporary SSH connection loss.
  • Improved reliable Cascade shutdown and removal on both VPS servers.
  • Improved the Test action for AmneziaWG and XRay.
  • The test creates a temporary connection on the VPS and measures download and upload speeds separately.
  • Results now show the handshake, latency, and actual traffic route: direct or through WARP.
  • Added an AmneziaVPN connection key in vpn:// format.
  • AmneziaWG configurations can now be imported into the official AmneziaVPN app using a QR code or connection key.
  • Standard .conf file export remains available for other compatible clients.
  • Updated the AmneziaWG and XRay icons.
  • Added protocol color coding to access and subscription lists.
  • Improved access filters: transport and source server can now be selected independently.
  • Filters are more compact and show the number of active conditions.
  • TLS Scanner now recovers automatically after a temporary local port conflict, and its status can be checked again.
  • Fixed SSH on Windows when SSH file paths contain spaces or special characters.

Version 1.5.3

  • Fixed an issue where an unavailable update server could block connecting to a healthy panel on a VPS.
  • Added fallback update sources for cases where the primary source is blocked or temporarily unavailable.
  • Improved update-check compatibility with antivirus software, proxies, and Windows system certificates.
  • Update checks now run separately and no longer interfere with working with an already installed panel.
  • Added protected update-data verification and more reliable switching between update sources.
  • Fixed Cascade on VPS servers where SSH uses a non-root user with passwordless sudo.
  • Cascade no longer requires manually adding the user to the Docker group or enabling root SSH login when passwordless sudo is available on the VPS.
  • Cascade permission errors now show a clear message instead of low-level Docker or panel response parsing errors.
  • Panel was updated to version 1.5.3 for a compatible release; existing VPS settings and client accesses are preserved.

Version 1.5.2

  • Added HAPP routing support for subscription links.
  • A subscription can now include a separate HAPP routing link, and HAPP receives routing rules through the routing HTTP header when the subscription is added or updated.
  • The public subscription page now shows when HAPP routing is enabled.
  • Launcher can now install and update panel not only as root, but also through a user with passwordless sudo.
  • VPS checks now show root/sudo access status and explain more clearly why installation is unavailable without root or passwordless sudo.
  • XRay and AmneziaWG access creation is more reliable on slow VPS servers.
  • If a VPS created an access but responded too late, launcher now tries to find the created access and open its QR, config, or link automatically.
  • XRay and AmneziaWG client list refreshes now tolerate slow VPS responses better.
  • Improved Cascade startup reliability on slow VPS servers and Docker configurations where the firewall backend is not detected directly.
  • After enabling Cascade, launcher checks that panel remains reachable on Entry and Exit VPS servers and automatically disables Cascade if reachability is not confirmed.
  • Cascade checks now wait longer for slow VPS servers and explain more clearly when the tunnel works but ping/ICMP is unavailable.
  • Fixed applying advanced AmneziaWG settings to client configs.
  • MTU, DNS, and I1 values configured in panel now correctly appear in new and reissued client configs.
  • Client DNS can now be configured manually; panel validates the format and prevents saving an invalid address list.

Version 1.5.1

  • Reduced background panel load on VPS servers while idle.
  • Optimized access, subscription, and limit state refreshes so unnecessary heavy checks are avoided.
  • Reduced short CPU spikes when checking limits, accesses, and subscriptions.
  • Improved subscription compatibility with Hiddify, Happ, and other apps that support subscription data.
  • Compatible apps now show the subscription name, expiration, used traffic, and subscription page link.
  • Compatible apps now use the subscription's own name without adding the Bandju Panel name.
  • Added the default caption: "Подписка создана в BandjuPanel".
  • The subscription rename window now includes fields for a custom caption and Telegram link.
  • When subscription limits are hidden, they are also omitted from compatible app data.

Version 1.5.0

  • A single subscription can now include XRay accesses from multiple VPS servers.
  • The subscription window now has a "+ Server" button for choosing accesses from another saved VPS.
  • Accesses from other VPS servers appear together with regular accesses: in the main table and inside the subscription.
  • These accesses show which server they came from. The server badge can quickly switch to the source VPS after confirmation.
  • Familiar actions work for accesses from other VPS servers: QR/link, rename, icon change, enable/disable, key or URL reset, WARP, and delete.
  • When deleting, choose whether to remove the access on the source VPS or only remove it from the current subscription.
  • Improved drag and drop between subscriptions, including accesses from other VPS servers.
  • The access list is clearer: subscriptions appear first, child accesses stay near their parent subscription, and accesses from other VPS servers are grouped by server.
  • Added "In subscription" and "External accesses" filters.
  • The shared subscription limit now works for subscriptions that include accesses from multiple VPS servers.
  • Panel sums traffic across all accesses inside the subscription and applies the shared limit to the whole subscription.
  • Accesses inside a subscription inherit its limit. Separate limits remain for standalone accesses outside subscriptions.
  • When an access is added to a subscription, its previous individual limit no longer interferes with the shared subscription limit.
  • If an access is already used in a subscription on another VPS, its local limit on the source server cannot be changed separately.
  • When a limit is exhausted, accesses are blocked by limit state without turning off the regular toggles.
  • Fixed blocking of accesses from other VPS servers when traffic or expiration limits are reached.
  • Old access traffic is no longer charged to a new subscription after adding the access to a subscription that is already limited.
  • Limit changes now appear in the interface faster.
  • The browser subscription page now works correctly with accesses from multiple VPS servers.
  • The page accounts for traffic, activity, and limit state for every access inside the subscription.
  • The limit is shown only on the subscription itself, without repeating it on every child access.
  • Improved display of total traffic and restrictions for subscriptions assembled from multiple VPS servers.
  • Added manual VPS diagnostics to the launcher.
  • It helps identify where the problem is: local computer, SSH connection, authorization, Docker, panel, or API.
  • It checks VPS connectivity, SSH, keys, known_hosts, local tunnel port, server state, Docker, panel container, and Panel API.
  • After the check, a short support report can be copied.
  • Passwords and private keys are not included in the report.
  • Diagnostics run only manually and do not change the computer or VPS.
  • Improved synchronization of accesses between VPS servers: rename, WARP, enable, and disable states are reflected more reliably in the launcher.
  • One access can now belong to only one subscription, even when subscriptions are on different VPS servers.
  • If an external VPS is temporarily unavailable, the launcher keeps the last known status and refreshes it when the server is reachable again.
  • The Accesses section opens faster and refreshes more reliably when switching VPS servers.
  • Quick actions in the access list are more reliable, especially when enabling or disabling multiple rows quickly.
  • Improved WARP toggles, including AmneziaWG and accesses from other VPS servers.
  • The dashboard opens faster and refreshes VPS status more reliably.
  • Improved resource display and CPU hints.
  • Added an "About" window with versions and official Bandju Panel contacts.
  • The launcher now checks more precisely which features are supported by panel on a specific VPS.
  • If panel on a server is outdated, the launcher blocks only actions unsupported by that server and shows a hint to update panel.

Version 1.4.0

  • Added the SSH Access module for managing VPS SSH keys directly from Bandju Panel.
  • VPS settings can now select the SSH key used for connection, create a new key, copy a public key, rename a key, or delete a private key.
  • If the selected SSH key is not accepted by the server, the launcher offers password login and helps update SSH access.
  • Improved SSH key handling on Windows and clearer errors for unsupported key files.
  • Added access limits: set a traffic limit and expiration date for an entire Access/subscription or for an individual connection.
  • Access is automatically blocked when the traffic limit or expiration date is reached, and manual disabling no longer conflicts with automatic blocking.
  • Subscription pages now show access limits, with an option to hide them.
  • Improved AmneziaWG configs after server port or settings changes.
  • Bandju Panel no longer requires manually refreshing each AmneziaWG config: the current QR code and .conf are returned when opening QR, downloading the config, or opening the subscription page.
  • Reopening an AmneziaWG QR is faster, and an old QR code should no longer briefly appear before the current one.
  • Doctor no longer performs bulk AmneziaWG config fixes or creates extra VPS load.
  • Improved interface resilience during long requests, temporary VPS check failures, and local SSH tunnel disconnects.
  • The dashboard now makes stale data clearer after a VPS reboot, reconnect, or tunnel loss.
  • Fixed cases where auto-refresh did not restart after panel updates, reconnects, or server switches.
  • In Lite mode, the access list should no longer stay empty after reconnecting to a server.
  • Fixed Cascade on Exit VPS hosts with non-standard network interface names.
  • Improved switching an active Entry VPS from one Exit VPS to another: the new Exit is saved correctly and stale data from the previous Exit is cleared after disconnecting.

Version 1.3.1

  • Fixed server switching on Windows: the launcher now clears stale local SSH tunnels so the selected VPS and the opened panel stay in sync.
  • Grouped access child rows in Accesses now use slightly larger text for better readability.

Version 1.3.0

  • Accesses have been redesigned around subscriptions: multiple XRay transports and AmneziaWG can be combined into one logical access.
  • Added stable public subscription links: /s/..., /raw, and /b64 for import into compatible clients.
  • The public subscription page now shows QR codes, links, traffic, AmneziaWG configs, .conf downloads, and app links for connecting.
  • Added access icons and flags: they are stored separately from names, shown in the list, and included in VLESS links for compatible clients.
  • Fixed flag rendering on Windows in the launcher and on browser subscription pages.
  • Accesses now support traffic period selection: total, day, week, month, and custom range.
  • Improved bulk actions, subscription drag and drop, filters, modals, row sync, and stale response protection.
  • Direct XRay links and AmneziaWG configs are easier to access from the unified Access modal.
  • Fixed dashboard load indicator rendering on Windows.
  • Improved Domain/Gateway startup recovery when the service starts slower than the first request.

Version 1.2.1

  • Added MTProto protection by unique IP count with the default limit set to 1000 to reduce VPS overload risk if a link leaks.
  • If a VPS cannot reach core.telegram.org, MTProto now shows clear warnings in the module, QR code, and Accesses.
  • Fixed XRay link generation after domain, SNI, or Gateway/self-SNI changes.
  • Fixed new XRay clients staying dimmed until manual refresh.
  • Improved server switching: the launcher updates the selected VPS state, Lite/Advanced mode, and update banners more reliably.
  • Full panel uninstall now cleans launcher SSH keys so bandju-launcher keys do not multiply across reinstall.
  • First module load now refreshes real VPS state more reliably instead of showing empty screens when data already exists.
  • RealiTLScanner now caches results and avoids rescanning every time.
  • Polished UI details: button states, progress overlays, fixed overlay width, long MTProto domains, service buttons, and the Windows taskbar icon.
